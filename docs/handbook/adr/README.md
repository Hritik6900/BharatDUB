# Architecture Decision Records

An ADR records one decision that shaped Bharat Dub (the v1 documents call it BharatDb): the problem, the options
that were really on the table, what we chose, and what it cost. Every number in an ADR is quoted from a source
file with its date and conditions, and labelled **measured**, **estimate**, **target** or **stand-in**. Where the
sources do not show that alternatives were weighed, the ADR says "not recorded" and marks reconstructed reasoning
"(unconfirmed)".

ADRs are not rewritten when a decision changes. A new ADR is written, and the old one gets `Superseded by:` (or a
note that it is complemented, e.g. ADR-0007 by ADR-0015).

## How to add one

1. Copy [`template.md`](template.md) to `NNNN-short-slug.md`, using the next free number.
2. Keep the headings in order: Context, Options considered, Decision, Consequences (Good, Bad), Evidence.
3. Keep the header lines exactly in this form (the index script reads them):
   `# ADR-NNNN: <title>`, `- **Status:** <status>`, `- **Date:** YYYY-MM-DD`, `- **Superseded by:** —`.
4. Status values: `proposed`, `accepted`, `superseded`, `deprecated`. A short qualifier may follow, e.g.
   `accepted (behind flag V1_X, default off)`.
5. Evidence links to experiments (`../experiments/EXP-NNN-slug.md`), commits (short hash in backticks) and source
   docs (relative links; the repo root is `../../../`).
6. Name the ADR in the commit message that makes the change: "... (ADR-NNNN)".
7. Add a row to the index below, or run `scripts/docs/gen_docs.py`, which rewrites the table between the markers.
