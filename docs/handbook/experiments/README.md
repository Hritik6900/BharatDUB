# Experiments

An **EXP** is the record of one measurement we made to answer one question: what we asked, what we expected,
how we set it up, the numbers, what they do not show, and what we decided. Bharat Dub (the v1 documents call it
BharatDb) is judged by measured numbers only; every number in [../RESULTS.md](../RESULTS.md) and
[../PITCH_FACTS.md](../PITCH_FACTS.md) points back to an EXP or to the report it came from.

An EXP is not a design decision. Decisions live in [../adr/](../adr/README.md); an EXP names the ADR it led to in
its `Decision` line, or says "none".

## Rules for every EXP

- Every number has its source (file and section), date, conditions, n (runs, lines, phrases) and spread, and a
  label: **measured**, **estimate**, **target** or **stand-in**.
- A date or detail that git or a document does not confirm is written "(unconfirmed)". Numbers are never invented
  or rounded into something better; quote them as the source gives them.
- Aggregates only. No transcripts, source text, translations, audio, voice samples, video ids, keys or addresses.
- Say what the material was. Most Live numbers come from one dense 24.9 s Hindi reel replayed at real-time speed,
  not from a live person; most Studio numbers from three 50 s test videos made with hosted stock voices.
- Say how many runs. Two equal Live runs have differed by about 10 points in timing and 6 in words heard back
  (`SPEC.md` section 17), so one run proves little.

## How to add one

1. Copy [TEMPLATE.md](TEMPLATE.md) to `EXP-NNN-short-slug.md`, with NNN the next free number (three digits).
2. Keep the header lines exactly as in the template: first line `# EXP-NNN: <title>`, then
   `- **Date:** YYYY-MM-DD`, `- **Status:** planned | partial | done`, `- **Decision:** ADR-NNNN ...` or `none`.
   The index below is generated from those lines.
3. Fill every section. Raw outputs stay in the data folder (`data-v1/eval/...`), never in git; per-phrase and
   per-job numbers go to `logs/` through `scripts/v1/collect-logs.py`.
4. Update [../RESULTS.md](../RESULTS.md): change the scoreboard row the EXP moves, add a row to the trend table
   if it is a new point in time, and link the EXP as the source.
5. Regenerate the index and the generated blocks of RESULTS.md: `python scripts/docs/gen_docs.py`.
6. Reference the id in the commit message, for example `... (EXP-NNN)`.
